# 🦾 OpenClaw Desktop & Host Applications Integration Guide

This guide explains how host macOS desktop applications (such as **OpenClaw Desktop**, **Bionics**, or any OpenAI-compatible client) connect to the local **QuarkDock** inference engine and Langfuse observability hub.

## ⚙️ OpenClaw Architecture & Wiring

OpenClaw separates its architecture into two distinct planes:

```
[OpenClaw macOS App] 
       │ 
       ▼ WebSocket (ws://127.0.0.1:18789) [Control Plane]
[OpenClaw Gateway Daemon] (Running on Mac host: PID 3536)
       │
       ▼ HTTP REST (http://127.0.0.1:8002/v1) [Inference Plane]
[QuarkDock Gateway :8002] ──► [Langfuse :3001] & [Host Ollama :11434]
```

### 1. Control Plane: OpenClaw macOS App
The macOS menu bar app connects to your local OpenClaw Gateway daemon:
- **Gateway URL**: `ws://127.0.0.1:18789` (or `127.0.0.1:18789`)
- **Auth Token**: Found in `~/.openclaw/openclaw.json` (under `gateway.auth.token`).

### 2. Inference Plane: Route OpenClaw Model Prompts to Langfuse
To automatically trace every agent prompt, tool execution, and token generated by OpenClaw into **Langfuse** on port `3001`:

Configure the model provider in `~/.openclaw/openclaw.json` to point to QuarkDock's OpenAI gateway:
```json
"models": {
  "providers": {
    "quarkdock": {
      "baseUrl": "http://127.0.0.1:8002/v1",
      "api": "openai",
      "apiKey": "quarkdock-local",
      "models": [
        {
          "id": "qwen2.5:7b",
          "name": "qwen2.5:7b",
          "contextWindow": 32768,
          "maxTokens": 8192
        }
      ]
    }
  }
}
```

Or connect directly to host Ollama (`http://127.0.0.1:11434`) if you want zero telemetry overhead.

## 🧪 Verifying Connectivity from macOS Terminal

### 1. Test Gateway Models List (OpenAI Wire Format)
```bash
curl -s http://localhost:8002/v1/models | jq .
```

### 2. Test Non-Streaming Chat Completion via Gateway
```bash
curl -s -X POST http://localhost:8002/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen2.5:7b",
    "messages": [
      {"role": "user", "content": "Respond in 3 words."}
    ],
    "stream": false
  }' | jq .
```

### 3. Test Streaming Inference via SSE
```bash
curl -N -s -X POST http://localhost:8002/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen2.5:7b",
    "messages": [{"role": "user", "content": "Count from 1 to 5."}],
    "stream": true
  }'
```

## 🚀 Performance on Apple Silicon (M5 Pro 24GB)

| Metric | Docker CPU Container (Previous) | Native Metal GPU on Host (Current) |
|---|---|---|
| **Inference Hardware** | 14 Linux CPU Cores (NEON) | Apple M5 Pro Metal GPU + Unified Memory |
| **Generation Throughput** | ~47 tokens/sec | **~55 – 85 tokens/sec** |
| **Time to First Token (TTFT)** | ~220 ms | **~90 – 140 ms** |
| **Docker Desktop RAM Footprint** | 12.0 GB RAM | **< 2.0 GB RAM** |
| **Machine Thermal / Fan Noise** | Warm / High Fan Activity | **Whisper-quiet / Cool** |
| **Langfuse Tracing** | Supported | Supported via `:8002/v1` Gateway |
